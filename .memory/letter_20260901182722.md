## 4. Verifizierte Fakten über die nyxCore-API (gegen den laufenden Endpunkt geprüft, nicht aus der Doku)

* Auth: `Authorization: Bearer nyx_mt_…` gegen `https://nyxcore.cloud/api/v1/mcp`.
  * **kein Header** → `{"error":"Bearer token required"}`
  * **ungültiger Token** → `{"error":"Invalid or expired token"}`
  * Die beiden auseinanderzuhalten war der Schlüssel zum Trimming-Bug.
* **`nyxcore_search` erreicht NUR Axiom.** `sources: ["insights","patterns"]` ändert nichts — alle Treffer kommen mit `"source": "axiom"`. Patterns/Insights gibt es ausschließlich über `nyxcore_get_patterns` / `nyxcore_get_insights`, beide **ohne** Query-Parameter.
* `nyxcore_search` **braucht `projectId`** bei tenant-scoped Tokens, sonst `isError` mit `missing_project_id`.
* Formen: `get_patterns` → `{patterns:[{type,title,description,evidence[],frequency,severity,tags}]}`, `type` ∈ success|pain|solution|pattern|tool|architecture. `get_insights` → `{insights:[{title,detail,insightType,category,severity,suggestion,tags,source}], total}`.
* **Axiom REST braucht vom „Knowledge endpoint" nur den Origin** — der Pfad `/api/v1/mcp` dort ist bei einem `nyx_ax_`-Token harmlos, `AxiomClient` hängt selbst `/api/v1/rag/search` an. Das hat den User verwirrt; die Feldbeschreibung sagt es immer noch nicht.
* Scope „All" schickt keinen Filter — gültig nur für ein wirklich tenantweites Token. Ein Token mit mehreren Projekten bekommt 400.
* Test-Projekt mit Patterns: `nyxcore-systems` `0fc12c6b-ca12-4a36-926c-801accad7385`. **`nyx.mdEdit` (`156add5c-…`) hat keine** — dort zum Testen ungeeignet.
